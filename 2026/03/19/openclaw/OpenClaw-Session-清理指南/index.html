OpenClaw Session 清理指南：为什么删了 transcript，session 还在？

在 OpenClaw 里清理旧 session 时，很多人会遇到一个很典型的问题：

  • sessions_list 里还能看到旧 session
  • 对应的 transcript 文件明明已经删了
  • 但 session 还是没有从列表里消失

这通常不是“没删干净”，而是因为 OpenClaw 的 session 不是只存一层。

这篇说明把原理、标准清理步骤、验证方式和安全注意事项一次讲清楚，适合之后直接照着操作。

一、先理解：OpenClaw 的 session 往往有两层存储

一个 session 通常涉及两部分内容：

1）transcript 文件

2）session 索引文件

关键结论

只删除 *.jsonl transcript 文件，通常并不足以让 session 从 sessions_list 里消失。

如果想彻底清理掉某个 session，通常需要同时处理两层：

  1. 删除 transcript 文件
  2. 删除 sessions.json 中对应的索引条目

第 1 步：先确认当前有哪些 session

第 2 步：确认你要删的是哪一个 session

  • agent:main:feishu:direct:ou_xxx

  • ~/.openclaw/agents/wenzhua/sessions/sessions.json
  • ~/.openclaw/agents/wanzhua/sessions/sessions.json

其他 agent 同理。

四、如何验证是否真的清理成功

清理完后，建议至少做一次复查。

方法 1：再次查看 session 列表

让 OpenClaw 再跑一次 sessions_list。

如果清理成功：

  1. 目标 session 不会再出现在列表里
  2. 列表总数会减少

方法 2：检查 transcript 文件是否还存在

如果提示不存在，说明 transcript 已经删掉。

方法 3：检查索引里是否还保留该 key

如果没有输出，说明索引条目已经被删除。

五、这次排查得到的核心结论

这次实际操作里，已经可以明确一个结论：

OpenClaw 的 session 清理通常要处理两层。

  1. 删除 transcript：
    • ~/.openclaw/agents/<agent>/sessions/<session-id>.jsonl
  2. 删除索引：
    • ~/.openclaw/agents/<agent>/sessions/sessions.json 中对应的 session key

如果只做第 1 步，很可能会出现：

transcript 没了，但 sessions_list 里还是能看到这个 session

这不是异常，而是因为索引还在。

七、建议的安全顺序

每次清理 session，建议按这个顺序执行：

  1. 先确认要删的是不是历史 session
  2. 先删 transcript 文件
  3. 再删 sessions.json 里的索引条目
  4. 最后用 sessions_list 或 grep 做复查

这样最不容易误删，也最容易定位问题出在哪一层。

八、哪些 session 不建议随便删

下面这些 session，建议先确认清楚再动：

  1. 当前正在使用的 session
  2. 长期角色型 agent 的活跃会话
  3. 还在运行的 cron 相关 session
  4. 后续还需要保留上下文的业务会话

如果只是“看起来旧”，但还没确认用途，先不要急着删。

九、一句话总结

OpenClaw 清理 session，不是只删 jsonl 就结束了。

想彻底从列表里消失，通常要同时处理两层：

  1. jsonl transcript
  2. sessions.json 索引

少删任意一层，都可能出现：

明明删了内容，但 session 还挂在列表里

这就是大多数“删不干净”的真正原因。
